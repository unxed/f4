# Localization (i18n) & Help System in f4

`f4` features a flexible, declarative localization system that allows translating both the user interface and the help files without recompiling the application.

## 1. How it works (The Fallback System)

To ensure the binary remains a single, portable executable, `f4` embeds the default English language (`en.lng`) and English help file (`en.hlf`) directly into the compiled application.

When `f4` starts, it follows this loading sequence:
1. Loads the embedded English strings.
2. Checks the user's `Language` preference in the configuration.
3. If the language is not English, it looks for an overriding `<language_code>.lng` file on disk.
4. Overlays any found translated strings on top of the English ones. If a translation is incomplete, the missing strings will safely fall back to English.

### Directory Structure
Language and help files are searched for in the following locations (in order of priority):
1. User profile: `~/.config/f4/lang/` and `~/.config/f4/help/` (or `%APPDATA%\f4\...` on Windows).
2. Portable app directory: `./lang/` and `./help/` relative to the `f4` executable.

## 2. Interface Translation (`.lng` files)

Language files use a standard INI format.

*   **`[Language]` section**: Contains metadata (Name, Code, Author). This is used to populate the Language selection menu (`F9 -> Options -> Language`).
*   **`[Strings]` section**: Contains the key-value pairs for the UI.

**Example `es.lng` (Spanish):**
```ini
[Language]
Name=Español
Code=es
Author=Translator Name

[Strings]
vtui.Ok=&Aceptar
vtui.Cancel=Cancelar
Menu.Files=Archivos
Quit.Confirm=¿Quieres salir de f4?
```
*(Note: Use `&` to define the keyboard shortcut/hotkey for a label or button. To display a literal ampersand, use `&&`)*.

## 3. Help File Translation (`.hlf` files)

Help files use a lightweight, Markdown-inspired format natively parsed by the `vtui` framework.

*   `@TopicName` defines a new help page anchor.
*   `$Sticky Title` defines a header that stays at the top of the screen while the user scrolls.
*   `~Link Text~TargetTopic@` creates a clickable hyperlink to another topic.
*   `#Bold Text#` highlights text.

If `f4` cannot find the help file for the current language (e.g., `es.hlf`), it will automatically fall back to the embedded `en.hlf`.

## 4. Source of Truth and Translation Invalidation

The embedded English strings (`en.lng` and `en.hlf`) are the absolute **Source of Truth** for the application. All other translations must align with them.

To handle changes elegantly without complex synchronization scripts, `f4` relies on the **Key Renaming** strategy:
*   **Fixing typos:** If an English string is modified to fix a typo but the *meaning remains the same*, the translation key remains unchanged. Existing translations are still perfectly valid.
*   **Semantic changes:** If the *meaning or context* of an English string changes (e.g., changing `"Copy"` to `"Copy to Clipboard"`), the developer MUST rename the translation key (e.g., from `Action.Copy` to `Action.CopyToClipboard`).

**Why Key Renaming?**
Because of the fallback system, changing the key immediately invalidates the old translation. The UI will safely display the new English string until translators update their respective `.lng` files with the new key. The old, orphaned keys will simply be ignored by the engine and can be periodically cleaned up.

## 5. The Translator Tool (`Ctrl+Alt+RightClick`)

To make translating `f4` as easy as possible, the application includes a built-in reverse-lookup tool for developers and translators.

If you see a string in the UI and want to know its translation key, simply hold **`Ctrl + Alt` and `Right-Click`** on the element (button, label, menu item, etc.).

`f4` will:
1. Perform a hit-test to find the exact UI component under your mouse.
2. Extract its current text.
3. Reverse-lookup the text in the active dictionary to find its `Key`.
4. Traverse the UI tree upwards to build a "Help Context" stack.
5. Copy a formatted report directly to your system clipboard.

**Example Clipboard Output:**
```text
--- f4 Translator Tool ---
Key:  PanelSettings.ShowHidden
Text: Show hidden and system files
Help Context: Panels -> Panel settings
```
You can then open your `.lng` file, search for `PanelSettings.ShowHidden`, and translate it.
For a detailed guide on how to report translation errors to the maintainers using this tool, see [L10N_REPORT_GUIDE.md](L10N_REPORT_GUIDE.md).

## 6. Ground Rules for Translators and Models

* `lang/en.lng` is the single source of truth. Keys are never translated, only values are.
* If the meaning of an English string changes, rename the key (see section 4). Do not silently reuse a key with a new meaning.
* `&` marks the hotkey letter, `&&` is a literal ampersand. The letter after `&` must actually occur in the translated word. In CJK languages, use the format `(&A)` with a Latin letter.
* `\n` is unescaped at load time. A translation must keep the same number of `\n` and exactly the same `%s` / `%d` / `%v` placeholders, in the same order, as the English original.
* Keep the key order of `en.lng`. It makes diffs and gap analysis readable.
* Do not shorten English texts just to make a layout fit unless a layout test demands it: the English string is what most users see.

### 7.1. Eliminating Hardcoded UI Strings
About 89 captions are still passed to `vtui` constructors as Go string literals. They are frozen in `tools/hardcoded_baseline.txt`. The goal is to reduce this baseline to zero.

**How to remove a hardcoded caption:**
1. Run `go run ./tools .` to see the list.
2. Add a key to `lang/en.lng` using the `Area.Thing` naming of the surrounding keys.
3. Replace the literal in the Go source with `Msg("Area.Thing")`.
4. Regenerate the baseline: `F4_UPDATE_HARDCODED_BASELINE=1 go test -run TestNoNewHardcodedUIStrings .`
5. Add the new key to every complete translation.

### 7.2. Widening the UI Scanner
The AST scanner currently understands `NewLabel`, `NewButton`, `NewCheckbox`, `NewCenteredDialog`, `NewVMenu`, `NewText` and the options slice of `NewComboBox`. It needs to be extended to menu items, input boxes, dialog titles assembled with `fmt.Sprintf`, and any vtui widget added later.

## 8. Recipes and Arithmetic

### 8.1. Adding a new language
Copy `lang/en.lng` to `lang/<code>.lng`, set `Name`, `Code` and `Author` in the `[Language]` section, translate the `[Strings]` section. Then run the tests.

### 8.2. Layout arithmetic
The layout validator (`TestAllDialogs_LayoutValidation`) checks that translations fit. If it fails, the fix is usually to shorten the caption by `got.X2 - allowed.X2` cells.

* A dialog of width `W` has usable columns `X1+2 .. X1+W-3`.
* Checkbox and button widths are `4 + len(caption)`. `&` is not printed. CJK characters occupy two cells.
* Label plus combo or edit of width `N` on one row: `len(label) <= W - 6 - N`.
* A checkbox on its own row: `len(caption) <= W - 8`.

### 8.3. Important Commands
```bash
go run ./tools .                                  # list hardcoded captions
go test -run TestNoNewHardcodedUIStrings .        # the CI gate
F4_UPDATE_HARDCODED_BASELINE=1 go test -run TestNoNewHardcodedUIStrings .
GOMAXPROCS=1 go test -run '^TestAllDialogs_LayoutValidation$' .
```
