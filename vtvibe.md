# vtvibe — ИИ-панель для f4

**Статус:** черновик концепции v1.0
**Целевой проект:** [`unxed/f4`](https://github.com/unxed/f4) — клон far2l на чистом Go
**Кодовое имя модуля:** `vtvibe` (в ряду `vtui` / `vtinput`)
**Аудитория документа:** разработчик или языковая модель средней мощности, реализующая фичу по шагам.

---

## 1. Быстрый старт

Это инструкция для тех, кто уже пробовал Google AI Studio в браузере
и хочет то же самое прямо в файловом менеджере, **бесплатно и не привязывая карту**.

Всё займёт минуты три. Ничего доустанавливать не нужно.

### Коротко: как это устроено

Панель ИИ в f4 — это **обычная панель с файлами**. Просто вместо диска на ней
лежит диалог с моделью.

Значит, никаких новых клавиш учить не надо:

* **F5** с левой панели на правую — «покажи модели вот этот файл»;
* **F5** обратно — «забери то, что модель написала»;
* **F3** — почитать; **F4** — поправить;
* **F8** — убрать из диалога.

Вопрос печатается в командной строке внизу, после `ai:`.

### Шаг 1. Взять бесплатный ключ (2 минуты)

1. Откройте **https://aistudio.google.com/apikey**
2. Войдите обычным гугл-аккаунтом (тем же, что и в почте).
3. Нажмите **Create API key** (создать ключ).
4. Скопируйте появившуюся строку. Она начинается на `AIza...`

Всё. Карту вводить не просят, счёт не выставят: пока вы не включили
биллинг вручную, работает бесплатный лимит, а при его исчерпании запросы
просто перестают проходить до следующего дня.

> Ключ — это как пароль. Никому не показывайте и не выкладывайте в чужие чаты.

### Шаг 2. Отдать ключ файловому менеджеру

Запустите f4 и наберите в командной строке внизу:

```
ai:key
```

Появится окошко — вставьте туда ключ и нажмите Enter.
Дальше спросят модель — просто нажмите Enter ещё раз, чтобы оставить как есть.

Ключ сохранится в файл `vtvibe.ini` в папке настроек f4, доступный только вам.

**Если предпочитаете переменные окружения** — можно вообще ничего не вводить,
f4 сам подхватит `GEMINI_API_KEY`:

```
export GEMINI_API_KEY=AIza...
```

### Шаг 3. Проверить, что всё живо

Наберите:

```
ai:models
```

Через пару секунд появится список моделей, до которых дотягивается ваш ключ.
Если список появился — всё работает.

Названия моделей у Google меняются несколько раз в год, поэтому **правильный
способ узнать актуальное имя — вот эта команда**, а не статья в интернете.
Понравилась какая-то из списка — переключитесь:

```
ai:model gemini-3.6-flash
```

(подставьте то имя, которое реально показал `ai:models`;
для бесплатного лимита берите модели со словом `flash` — они самые щедрые)

### Шаг 4. Первый диалог

1. Нажмите **Ctrl+Alt+A** — на второй панели откроется диалог с моделью.
   (то же самое: **Alt+F1** / **Alt+F2** → пункт **AI** в списке дисков)
2. Зайдите на панели диалога в папку **`ctx`** (Enter на ней).
3. Перейдите **Tab**'ом на панель с вашими файлами, встаньте на нужный файл
   или папку и нажмите **F5**. Файл уехал в контекст — теперь модель его видит.
4. Наберите внизу вопрос:

```
ai: что делает этот файл и что в нём не так?
```

Пойдёт полоска прогресса (её всегда можно прервать кнопкой Cancel),
а ответ откроется в обычной смотрелке f4. Esc — выйти.

Дальше можно спрашивать ещё: модель помнит предыдущие вопросы и ответы.

### Шаг 5. Забрать результат

Вся переписка лежит файлами, её можно листать и перечитывать:

| Где | Что лежит |
| --- | --- |
| `ctx/` | то, что вы дали модели. Убрать — **F8** |
| `chat/` | история: по файлу на каждое сообщение |
| `out/` | целые файлы, которые выдала модель |
| `draft.md` | черновик длинного вопроса |
| `session.md` | текущие настройки и подсказки по клавишам |

Если модель написала целый файл, он появится в **`out/`**.
Встаньте на него, **F3** — посмотреть, **F5** — положить к себе на диск.

**Длинный вопрос** удобнее писать в редакторе: **F4** на `draft.md`,
пишете сколько нужно, **F2** — сохранить, потом наберите просто `ai:`
(двоеточие и ничего после него) — уедет содержимое черновика.

### Все команды

| Команда | Что делает |
| --- | --- |
| `ai: ваш вопрос` | спросить модель |
| `ai:` | отправить `draft.md` |
| `ai:models` | список доступных моделей |
| `ai:model ИМЯ` | сменить модель |
| `ai:key` | ввести ключ доступа |
| `ai:new` | начать диалог с чистого листа (файлы в `ctx/` останутся) |
| `ai:help` | эта шпаргалка |

Плюс пункты в меню **F9 → Команды** и клавиша **Ctrl+Alt+A**.

### Если что-то пошло не так

**«Ключ доступа не найден»** — не выполнен шаг 2. Наберите `ai:key`.

**Ошибка со словами `models/... is not found`** — имя модели устарело.
Наберите `ai:models` и возьмите любое имя из списка.

**Ошибка `HTTP 429`** — упёрлись в бесплатный лимит (он считается на минуту
и на сутки). Подождите минуту и повторите; f4 сам делает несколько попыток.
Если повторяется часто — возьмите модель полегче, со словом `flash-lite`.

**Ошибка `HTTP 400`** — обычно слишком много всего в `ctx/`.
Уберите лишнее клавишей **F8**.

**Ответ приходит долго** — это нормально для большого контекста.
Нажмите Cancel в окне прогресса, если передумали ждать.

### Что вообще уезжает в интернет

Только то, что вы сами положили в `ctx/`, плюс текст ваших вопросов.
Больше ничего: ни ваш диск целиком, ни соседние папки.
Посмотреть глазами, что там лежит, можно всегда — это обычные файлы.

Файлы, похожие на секреты (`.env`, `id_rsa`, `*.pem`, `credentials`, всё из `.ssh`),
**не отправляются вообще**, даже если случайно попали в `ctx/` —
вместо содержимого модель увидит только строчку о том, что файл пропущен.

И имейте в виду: на бесплатном лимите Google оставляет за собой право
использовать переписку для улучшения своих продуктов. Для рабочих секретов
это не место — берите платный тариф или локальную модель.

### Не только Google

Панель говорит на общепринятом протоколе, поэтому её можно направить
куда угодно. Файл `vtvibe.ini` в папке настроек f4:

```ini
[general]
base_url = https://generativelanguage.googleapis.com/v1beta/openai
model    = gemini-3.6-flash
key      = AIza...
```

Другие варианты — поменяйте `base_url` и `model`:

* **OpenRouter** — `https://openrouter.ai/api/v1` (там есть бесплатные модели)
* **Ollama** — `http://127.0.0.1:11434/v1`, ключ не нужен вовсе
* **LM Studio** — `http://127.0.0.1:1234/v1`, ключ не нужен вовсе

Локальные модели — это полностью бесплатно и никуда не уходит из дома.

### In English

The AI panel mounts a model's context as an ordinary drive, so the usual
keys keep their meaning: **F5** copies a file into the dialog, **F5** copies
the model's answer back to disk, **F3**/**F4** read and edit, **F8** drops.

Getting started with the free Google AI Studio tier:

1. Get a key at https://aistudio.google.com/apikey (no credit card required).
2. In f4, type `ai:key` in the command line and paste it.
3. Type `ai:models` to see which models the key can reach, then
   `ai:model <name>` to pick one. Model names change often — ask the command,
   not the documentation.
4. Press **Ctrl+Alt+A**, copy a file into `ctx/` with **F5**, then ask:
   `ai: what does this file do?`

The dialog lives in `chat/`, whole files written by the model land in `out/`,
and `draft.md` is there for long prompts (**F4**, **F2**, then a bare `ai:`).
Settings are in `vtvibe.ini` in the f4 config directory; the key is also read
from `GEMINI_API_KEY`. Point `base_url` at OpenRouter, Ollama or LM Studio to
use anything else.

## 2. Эволюция UX: От «Всё есть VFS» к гибридному чату (Пивот)

Изначальная концепция предполагала, что *абсолютно всё* взаимодействие с моделью происходит через файловую систему (`chat/0001-user.md`, редактирование `draft.md` и т.д.). Однако фидбек от early adopter'ов показал, что такой подход хорош как мощный движок («под капотом»), но слишком громоздок для повседневного общения. Пользователи хотели привычный визуальный чат с историей и многострочным полем ввода.

**Текущая архитектура (v1.0): Гибридная панель в отдельном воркспейсе.**
Мы сохранили `AIVFS` как основу (чтобы работало копирование по `F5`, извлечение патчей из `out/afix.ap` и сбор контекста из `ctx/`), но скрыли её за удобным фасадом `AIChatPanel`. Эта панель реализует интерфейс `AltPanel` (подобно QuickView) и накладывается поверх файловой:
1. **Отдельный воркспейс:** Вызов ИИ (`Ctrl+Alt+A` или `Ask the AI`) автоматически клонирует панели в новый воркспейс (вкладку), разворачивая панель ИИ на весь экран. Вы можете моментально переключаться между кодом и чатом по `Ctrl+Tab`.
2. **Умный контекст:** Команда `Ask the AI` не просто открывает чат, она «захватывает» ваше текущее состояние (путь на панели, выделенные файлы, имя открытого в редакторе файла и строку под курсором) и передаёт его модели.
3. **Бесшовное переключение:** Горячие клавиши `Ctrl+1..4` позволяют на лету менять визуальный режим: Чат, Контекст (`ctx/`), Артефакты (`out/`), Память (`mem/`).

**Выполненные задачи текущей сессии:**
- [x] Реализована `AIChatPanel` (поверх `AIVFS` как `AltPanel`).
- [x] Команда `Ask the AI` открывает отдельный воркспейс и собирает глубокий контекст (UI, Editor, Viewer, выбранные файлы).
- [x] Онбординг API-ключа: предложение получить ключ с открытием браузера.
- [x] Горячие клавиши `Ctrl+1..4` перехватываются *нативно* (без глобальных костылей) через интерфейс `PanelController`, реализованный поверх `AIVFS`.
- [x] Динамическое перестроение меню: стандартные режимы вида скрыты в панелях ИИ, и заменены на режимы ИИ.
- [x] Перехват `Shift+Стрелок` и `Shift+Enter` (многострочный ввод) в чате.
- [x] Поддержка `googleSearch` и контекста URI по умолчанию для моделей Gemini.
- [x] Кликабельные ссылки Markdown (`ai://...`) и навигация по ним через `Tab`.

**План на следующую итерацию:**
- Подсветка синтаксиса (Colorer) для ответов модели.
- Выделение текста (`Ctrl+A`, `Shift+Стрелки`) и поддержка копирования в `MultiLineEdit`.

Модель по-прежнему выдаёт `ap`-патчи, которые попадают в `out/` и ревьюятся человеком.

## 1. Что мы переиспользуем в f4 (и чего не пишем заново)

Перед реализацией прочитайте в репозитории: `VFS.md`, `PLUGINS.md`, `UX_GUIDELINES.md`, `TERMINAL.md`.

| Уже есть в f4 | Как используем в vtvibe |
|---|---|
| Асинхронный VFS (`ReadDir(ctx, path, onChunk)`, `ErrLoading`) | `ai://` — обычный VFS-диск. Панель контекста бесплатно получает неблокирующую отрисовку и отмену. |
| Реестр действий `action_registry.go` | Все команды vtvibe — записи реестра. Меню `F9`, KeyBar, макросы и справка генерируются сами. |
| `EditorView` на Piece Table | Черновик промпта, просмотр ответа, панель диффа в ревью патча. |
| `ViewerView` | `F3` по записи контекста — просмотр точного «экстракта». |
| `ScreenBuf` (двойная буферизация, побитовый дифф) | Сериализация экрана в текст для самодиагностики (см. §12). |
| Фоновый менеджер задач (`Host.RunProgressTask`) | Все сетевые вызовы, индексация, сборка. |
| Диалоги `vtui` (`Dialog`, `VMenu`, `Table`, `Edit`, `ComboBox`) | Мастер настройки, выбор роли, ревью патча. |
| `ini.go` | Формат конфига vtvibe. |
| `lang/en.lng`, `lang/ru.lng` | Локализация всех новых строк — обязательна. |
| Макросы + `Actions.Run(...)` | Автоматизация и воспроизводимые сценарии для самотестирования. |

**Правило:** не тащить в f4 новые тяжёлые зависимости. Сборка должна остаться `CGO_ENABLED=0 go build .`. Всё, что нужно для работы с HTTP-API моделей, — это `net/http`, `encoding/json` и ~400 строк разбора SSE. Готовые «фреймворки для агентов» тянут за собой десятки модулей, навязывают чужую модель управления (как раз ту агентскую, которую мы не хотим) и ломают философию «нет ада зависимостей». Если очень хочется чужой SDK — он должен жить во **внешнем плагине** через F4-RPC, а не в ядре.

## 2. Семь принципов

1. **Контекст — это файлы.** Всё, что модель увидит, должно быть видно человеку как файл, в панели, с размером и с возможностью открыть `F3`. Никакого невидимого «магического контекста».
2. **Человек одобряет каждую запись на диск.** Модель предлагает — f4 показывает — человек нажимает. Автоприменение существует, но включается явным флагом и всегда обратимо.
3. **Обратная связь раньше токенов.** Ошибка сборки, непонятый запрос, неприменившийся патч — всё это должно вернуться в диалог за одно нажатие и как можно раньше.
4. **Мышечная память священна.** Ни одна клавиша не должна поменять смысл. `F5` всегда копирует из активной панели в пассивную — просто одна из панелей теперь модель.
5. **Ноль конфигурации на старте.** vtvibe обязан работать вообще без API-ключей (режим буфера обмена, §6.3.5). Ключи — оптимизация, а не входной барьер.
6. **Дешёвая модель делает, дорогая думает.** Архитектура должна поддерживать два одновременных сеанса с передачей «наряда» между ними одним нажатием `F5`.
7. **f4 умеет описывать сам себя.** TUI — единственный GUI, который сериализуется в текст без потерь. Это надо использовать (§12).

## 3. Главная идея: `ai://` — контекст как файловая система

### 3.1. Пространство имён

```
ai://<session>/
    session.md          сводка: провайдер, модель, роль, токены, стоимость (только чтение)
    draft.md            черновик следующего сообщения; F4 открывает его в редакторе
    ctx/                ЧТО УЕДЕТ В СЛЕДУЮЩИЙ ЗАПРОС
        <зеркало путей проекта>
        _run/           автособранные артефакты: вывод сборки, тестов, git diff
        _f4/            синтетические файлы самодиагностики (§12.1)
    chat/               история диалога, по файлу на сообщение
        0001-user.md
        0002-model.md
        ...
    out/                артефакты последнего ответа
        afix.ap
        <прочие файлы, которые модель выдала целиком>
    mem/                проекция постоянной памяти проекта (.vtvibe/, §10)
        project.md
        map.md
        rules/
    presets/            роли и системные промпты
        architect.md
        coder.md
```

Сеансов может быть несколько: `ai://architect/…`, `ai://coder/…`. Корень `ai://` показывает список сеансов; `F7` в корне создаёт новый сеанс, `F8` — закрывает.

### 3.2. Почему именно так

Потому что тогда **не нужно изобретать UI**. Панель контекста — это `Table`. Просмотр экстракта — это `ViewerView`. Правка промпта — это `EditorView` со всеми макросами, подсветкой и закладками. Выделение группы записей — `Ins`, `Серый +`, `Ctrl+A`. Сравнение «что было / что предлагает модель» — штатное сравнение папок. Копирование результата — `F5`. Мы получаем девяносто процентов интерфейса даром и, что важнее, **бесплатно получаем предсказуемость**.

### 3.3. Что такое «запись контекста»

Запись — не обязательно целый файл. Это ссылка на источник плюс срез:

```go
// vtvibe/context.go
type CtxKind int

const (
    CtxFile     CtxKind = iota // файл целиком
    CtxFragment                // диапазон строк файла
    CtxDir                     // рекурсивно, с фильтрами
    CtxSynthetic               // сгенерировано f4 (вывод сборки, дамп экрана)
    CtxMemory                  // из .vtvibe/, всегда идёт в начало запроса
)

type CtxMode int

const (
    ModeRO CtxMode = iota // модель видит, но менять не должна
    ModeRW                // модель может выдавать правки для этого файла
)

type CtxEntry struct {
    ID        string   // стабильный, для ссылок из UI и логов
    Kind      CtxKind
    Mode      CtxMode
    Path      string   // путь относительно корня проекта
    FromLine  int      // 1-based; 0 = с начала
    ToLine    int      // 0 = до конца
    Pinned    bool     // не выкидывать при сжатии контекста
    Label     string   // человеческая пометка, попадает в промпт
    Hash      string   // sha256 содержимого на момент добавления
    Stale     bool     // файл изменился на диске после добавления
    Tokens    int      // оценка, кэш
    AddedBy   string   // "user" | "relevance" | "auto-run" | "model-request"
}
```

**`Stale` — важная мелочь.** Если файл в контексте изменился на диске (вы применили патч, переключили ветку), запись подсвечивается другим цветом и в статусной строке появляется счётчик. `Ctrl+R` перечитывает всё устаревшее. Без этого модель регулярно рассуждает о коде, которого уже нет, — и это одна из самых дорогих ошибок в таком воркфлоу.

### 3.4. Реализация как VFS-провайдер

Внутренний Go-провайдер (по образцу архивного и NetFox), статически слинкованный, но использующий тот же концептуальный `HostAPI`. Регистрируется как диск с меткой `AI` и появляется в меню `Alt+F1` / `Alt+F2`.

Обязательные методы (см. `PLUGINS.md`, §2A):

- `VFS.ReadDir` — потоковая выдача записей; для `chat/` отдавать порциями, история может быть длинной.
- `VFS.Stat`.
- `VFS.Open` / `VFS.ReadAt` — **обязательно**, иначе `F5` из `ai://` наружу молча не сработает: копирование в f4 идёт через `Open`+`ReadAt`.
- `VFS.Create` / `VFS.Write` — приём файлов, скопированных в `ai://ctx/`.
- `VFS.Remove` — `F8` в контексте.
- `VFS.Rename` — `F6` в контексте меняет `Label`.
- `VFS.ProcessKey` — перехват клавиш, специфичных для панели (`Ctrl+A`, `Alt+F5`, `Esc`).

## 5. Центральный сценарий: архитектор слева, кодер справа

Это то, ради чего затевается двухпанельность, и это должно быть реализовано в M4, а не «когда-нибудь».

```
╔═════ ai://architect [думает] ══════════╦═════ ai://coder [делает] ═════════════╗
║ /chat                                  ║ /ctx                                  ║
║ /ctx                                   ║  ⚑ mem/project.md                     ║
║ /out                                   ║  ⚑ mem/rules/ap.md                    ║
║   order-014.md      ← курсор           ║    file_panel.go                      ║
║   afix.ap                              ║    file_panel_test.go                 ║
╟────────────────────────────────────────╫───────────────────────────────────────╢
║ роль: architect · <дорогая модель>     ║ роль: coder · <дешёвая модель>        ║
╚════════════════════════════════════════╩═══════════════════════════════════════╝
                     F5  →  наряд уехал кодеру в контекст
```

Как это работает:

1. Роль `architect`: дорогая модель, широкий контекст, **запрещено выдавать патчи**. Её продукт — `order-NNN.md`: наряд на работы. Формальные разделы: цель, затрагиваемые файлы, ограничения, пошаговый план, критерии приёмки, тесты, которые должны позеленеть.
2. Человек читает наряд (`F3`), правит (`F4`), выкидывает лишнее.
3. `F5` — наряд копируется в `ai://coder/ctx/`. Буквально та же клавиша, которой вы двадцать лет копировали файлы.
4. Роль `coder`: дешёвая модель, узкий контекст (наряд + перечисленные в наряде файлы + правила `ap`), **обязана отвечать патчем `ap`**.
5. Патч уходит в ревью (§7.3). Отклонённые правки с причинами возвращаются кодеру.
6. Если кодер трижды подряд не справился — `Alt+F6` эскалирует: весь тред кодера пакуется и уезжает архитектору с вопросом «почему не выходит».

Технически «сеанс» — это просто отдельный экземпляр `Session` со своим провайдером, ролью и контекстом. Двухпанельность здесь не метафора, а буквальная реализация: два независимых VFS-корня.

## 6. Провайдеры моделей

### 6.1. Интерфейс

```go
// vtvibe/provider/provider.go
package provider

type Role string

const (
    RoleSystem Role = "system"
    RoleUser   Role = "user"
    RoleModel  Role = "model"
)

type Message struct {
    Role  Role
    Text  string
    // Files — вложения для провайдеров, которые их умеют.
    // Кто не умеет — пакует их в текст через vtpack (§8.1).
    Files []Attachment
}

type Attachment struct {
    Name     string
    MimeType string
    Data     []byte
}

type Request struct {
    Model       string
    System      string
    Messages    []Message
    MaxTokens   int
    Temperature float64
}

type EventKind int

const (
    EventDelta EventKind = iota // кусок текста
    EventUsage                  // сведения о токенах
    EventDone
    EventError
)

type Event struct {
    Kind   EventKind
    Text   string
    In     int   // входные токены (для EventUsage)
    Out    int   // выходные токены
    Err    error
}

// Stream отдаёт события до закрытия канала.
// Отмена ctx ОБЯЗАНА прерывать генерацию и закрывать соединение.
type Provider interface {
    Name() string
    Models(ctx context.Context) ([]string, error)
    Stream(ctx context.Context, req Request) (<-chan Event, error)
}
```

Всё остальное в vtvibe работает только через этот интерфейс. Ни одна строка UI не должна знать про конкретного вендора.

### 6.2. Транспорт: требования

- Только `net/http`. SSE разбирается вручную: `bufio.Scanner` по строкам, накопление `data:`, пустая строка = конец события. Это меньше двухсот строк.
- Тайм-аут на установление соединения — 30 с. Тайм-аута на весь ответ **быть не должно** (длинные генерации), но должен быть тайм-аут бездействия: если поток молчит 120 с — ошибка.
- Ретраи только на `429` и `5xx`, экспоненциальная задержка, максимум 3 попытки, уважать `Retry-After`. На `4xx` (кроме 429) ретраев нет.
- Все вызовы — через фоновый менеджер задач, с прогрессом и работающей кнопкой «Отмена». UI-поток не блокируется никогда.
- Прокси — из переменных окружения (`HTTPS_PROXY`), плюс явная настройка в конфиге.

### 6.3. Реализации

#### 6.3.1. `anthropic`
Messages API, потоковый режим. Системный промпт — отдельным полем. Учёт токенов приходит в событиях потока — использовать его как источник истины вместо локальной оценки.

#### 6.3.2. `google`
Generative Language API, потоковая генерация. Системная инструкция — отдельным полем. Роль модели называется иначе, чем у остальных, — маппинг делать в адаптере, наружу отдавать `RoleModel`.

#### 6.3.3. `openai-compatible`
Одна реализация закрывает огромное поле: OpenRouter, локальные `llama.cpp` / LM Studio / vLLM / Ollama, и почти всех прочих. Настраивается `base_url` + `api_key` + `model`. Это самый ценный по соотношению «строк кода / охват» провайдер — делать его первым.

#### 6.3.4. `exec` — любой CLI как провайдер
Запуск внешней команды, промпт в `stdin`, ответ из `stdout`, потоково.

```ini
[provider.mycli]
type = exec
command = some-llm-cli --print --model {{model}}
stream = true
```

Зачем: покрывает подписочные CLI-инструменты, где нет API-ключа; покрывает локальные модели; покрывает всё, что появится в будущем, без правки f4. Это ваш аварийный люк.

#### 6.3.5. `clipboard` — работа вообще без ключей

**Это ключевая фича для низкого порога входа, а не курьёз.** Многие (включая автора f4) пользуются моделями по подписке через веб-интерфейс, а API-ключей у них нет.

- «Отправить» = сформировать полный текст запроса (§8.3), положить в системный буфер обмена, опционально открыть браузер по настроенному URL, показать модальное окно «Вставьте ответ и нажмите F5».
- «Получить» = `F5` из буфера обмена в `ai://in/`. Дальше всё идёт по обычному конвейеру: парсинг `ap`, ревью, применение.
- Всё остальное — контекст, поиск релевантных файлов, память, ревью патчей, откат — работает **точно так же**. Отличается только транспорт.

Человек ставит f4, нажимает `Alt+F2`, выбирает `AI`, и через тридцать секунд у него работает нормальный воркфлоу без единой регистрации где-либо. Это и есть «супер низкий порог входа».

### 6.4. Ключи

Порядок разрешения, первый непустой выигрывает:

1. Переменная окружения (`ANTHROPIC_API_KEY`, `GEMINI_API_KEY`, `OPENAI_API_KEY`, …).
2. `key_command` в конфиге — команда, печатающая ключ в stdout (`pass show ai/anthropic`, `secret-tool lookup …`). Позволяет пользоваться любым менеджером паролей без единой зависимости.
3. `~/.config/f4/vtvibe/keys.ini`, права `0600`. При правах шире — предупреждение при старте.

**Категорически запрещено:**
- писать ключи в `debug.log`; в логгер добавить редактор-фильтр, вырезающий значения известных ключей и всё, похожее на токен (`sk-…`, длинные base64);
- класть ключи в `.vtvibe/` внутри проекта (это каталог под git);
- отправлять ключи куда-либо, кроме соответствующего провайдера.

Никаких CGO-зависимостей ради системного keyring: `key_command` решает ту же задачу нулём зависимостей.

### 6.5. Токены, бюджет и «предполётная проверка»

Точный токенизатор в ядро не тащим. Достаточно:

- Оценка `len(utf8-байт) / 3.6` для латиницы и кода, `/ 2.2` для кириллицы. Ошибка порядка 10–15 %, для индикатора хватает.
- После первого же ответа берём **фактические** цифры из `EventUsage` и калибруем коэффициент для этого провайдера. Через два-три обмена оценка становится точной.

**Предполётная проверка** — обязательная. Перед отправкой: если оценка превышает `soft_limit` (по умолчанию 60 % окна модели), показать диалог:

```
┌──────────── Предполётная проверка ─────────────┐
│ Запрос:      ~ 84 200 токенов (42% окна)       │
│ Крупнейшее:  vendor/big.go          31 400     │
│              testdata/dump.json     18 900     │
│                                                │
│ [ Отправить ] [ Убрать крупнейшее ] [ Отмена ] │
└────────────────────────────────────────────────┘
```

Кнопка «Убрать крупнейшее» — не украшение. Именно так люди случайно отправляют `node_modules`.

Индикатор в статусной строке панели: `8 889/200 000 ток · 4.4%`. Цвет меняется на `AIBudgetWarn` после 60 %.

## 7. Патчи: как принимать изменения от модели

### 7.1. Почему `ap`, а не diff и не «правь файлы сам»

`ap` (см. [spec](https://github.com/unxed/ap/blob/main/ap.md)) выбран потому, что:

- он ищет место по **семантическому сниппету**, а не по номерам строк, — модели плохо считают строки;
- директивы префиксованы случайным восьмисимвольным hex-ID, поэтому не нужно экранирование и невозможна коллизия с содержимым;
- он **идемпотентен** по спецификации: повторное применение не ломает файл, а сообщает «уже применено»;
- в нём предусмотрены эвристики устойчивости («мягкое начало, строгий хвост», авто-коррекция диапазонов, разрешение неоднозначных якорей) — то есть он прощает ровно те ошибки, которые модели делают чаще всего;
- он уже проверен вами в бою.

Рассмотренные альтернативы и почему нет:

| Вариант | Почему нет |
|---|---|
| Unified diff | Номера строк, точные пробелы. Модели их ломают. |
| «Выдай файл целиком» | Дорого по токенам, ломается на длинных файлах, невозможно ревьюить по частям. |
| Инструменты/tool calls с построчным редактированием | Привязка к вендору, много раундтрипов, плохой контроль, и это уже агентский flow. |
| Search/replace-блоки (как в ряде агентов) | Близко к `ap`, но без ID-префикса нужны экранирование и угадывание границ. |

**Вывод:** `ap` — основной формат. Опционально поддержать чтение unified diff **на вход** (люди приносят патчи откуда угодно), но генерации от модели просить только `ap`.

### 7.2. Аппликатор: требования к реализации на Go

Пакет `vtvibe/ap/`. Реализовать по спецификации 3.1, обязательно:

- Разбор заголовка `[ID] AP 3.1`; терпимость к отсутствию заголовка и к комментариям `#` до него (извлечь ID из первой директивы).
- Директивы: `FILE` (с необязательным `LF|CRLF|CR`), `REPLACE`, `INSERT_AFTER`, `INSERT_BEFORE`, `DELETE`, `CREATE`, `RECREATE`, `RENAME`, `snippet`, `snippet_tail`, `anchor`, `content`, `include_leading_blank_lines N`, `include_trailing_blank_lines N`, `END`.
- Нормализованный поиск: выбросить пустые строки локатора, обрезать пробелы по краям каждой строки, искать последовательность непустых строк.
- Граничные якоря `^` (начало файла) и `$` (конец файла).
- Правила уникальности: `anchor` — ровно одно вхождение; `snippet` без якоря — ровно одно; со `anchor` — первое после якоря.
- **Последовательный курсор:** после успешно рассчитанной правки все дальнейшие поиски в этом файле начинаются после её конца.
- Идемпотентность по каждому действию — по таблице из §3.1 спецификации.
- Эвристики устойчивости из §3.6 спецификации: гибридный поиск, авто-коррекция диапазона, разрешение неоднозначного якоря, `anchor` как `snippet`, неявный `CREATE`.
- Пост-обработка: обрезать хвостовые пробелы **только** во вставленном контенте, не трогать остальной файл.
- **Всё считается в памяти**, на диск пишется только после подтверждения человеком.

**Ограничения безопасности (сверх спецификации, обязательно):**

- Путь из `FILE` не может содержать `..`, не может быть абсолютным, не может выходить за корень проекта после разрешения симлинков.
- `RENAME` подчиняется тем же правилам для цели.
- Запись разрешена только в файлы, которые либо помечены `ModeRW` в контексте, либо создаются заново внутри корня. Попытка тронуть `ModeRO`-файл — не ошибка, а **предупреждение в ревью**: правка показывается, но по умолчанию выключена.
- Максимальный размер патча — 5 МБ, максимум 200 правок. Больше — почти наверняка сбой генерации.

### 7.3. Экран ревью патча

Отдельный экран (уровень 0 навигации, переключается `Ctrl+Tab`), а не модальный диалог: человек должен иметь возможность уйти в редактор и вернуться.

```
╔════════════════════ Ревью патча · afix.ap ══════════════════════════════╗
║ Правки (4)                    ║ vfs/ai_vfs.go   REPLACE   ✔ найдено     ║
║ ───────────────────────────── ║ ─────────────────────────────────────── ║
║[x] vfs/ai_vfs.go   REPLACE ✔  ║  117  }                                 ║
║[x] vfs/ai_vfs.go   INSERT  ✔  ║  118                                    ║
║[ ] vtvibe/pack.go  REPLACE ⚠  ║  119  func (d *aiDrive) Open(           ║
║[ ] go.mod          REPLACE ✖  ║  120      ctx context.Context, p string ║
║                               ║ -121      return 0, ErrNotSupported     ║
║ ✔ применимо                   ║ +121      e, ok := d.lookup(p)          ║
║ ⚠ неоднозначно (2 совпадения) ║ +122      if !ok {                      ║
║ ✖ сниппет не найден           ║ +123          return 0, ErrNotFound     ║
║ ≡ уже применено               ║ +124      }                             ║
║ ⛔ файл помечен RO             ║ +125      return d.openEntry(ctx, e)    ║
║                               ║  126  }                                 ║
╟───────────────────────────────╨─────────────────────────────────────────╢
║ Итого к применению: 2 правки в 1 файле                                  ║
╟─────────────────────────────────────────────────────────────────────────╢
║ Пробел вкл/выкл  Enter в файл  F5 применить  F8 отклонить с причиной     ║
║ F3 весь патч  F6 сухой прогон  Ctrl+Z откат  Esc выход                  ║
╚═════════════════════════════════════════════════════════════════════════╝
```

Клавиши:

| Клавиша | Действие |
|---|---|
| `Пробел` | Включить/выключить правку |
| `Ins` / `Серый +` / `Серый -` | Групповое выделение, как в панели |
| `Enter` | Открыть реальный файл в редакторе на месте правки |
| `F3` | Посмотреть исходный текст `.ap` целиком |
| `F5` | Применить включённые правки |
| `F6` | Сухой прогон: применить в память, показать, что получится, ничего не писать |
| `F8` | **Отклонить с причиной** — диалог, текст причины уходит в черновик следующего сообщения |
| `Ctrl+Z` | Откатить последнее применение |
| `Tab` | Переключение список ↔ дифф |
| `Esc` | Выйти, состояние сохраняется |

**`F8` «отклонить с причиной» — самое важное здесь.** Он замыкает петлю обратной связи: вместо того чтобы вручную объяснять модели, что не так, вы жмёте одну клавишу на конкретной правке, пишете полторы строки, и в следующем запросе модель получает структурированный список отклонений с точной привязкой к своим же правкам.

Дифф рисуем существующим `EditorView` в режиме «только чтение» с подсветкой через штатный highlighter. Не писать свой рендерер диффа.

### 7.4. Транзакции и откат

Перед применением патча:

1. Снять снимок затрагиваемых файлов в `.vtvibe/undo/<timestamp>/`.
2. Записать журнал: список файлов, хеши до, хеши после.
3. Применить всё атомарно: сначала посчитать все результаты в памяти, потом записать. Если запись любого файла упала — восстановить из снимка и сообщить.
4. `Ctrl+Z` в панели или в ревью откатывает последнюю транзакцию. Глубина по умолчанию — 20 транзакций.

Если проект под git — дополнительно предложить `git stash` перед применением, но **не делать этого автоматически**: чужим репозиторием распоряжаться нельзя.

## 8. Отправка: как контекст превращается в запрос

### 8.1. `vtpack` — склейка дерева в один файл

Некоторые модели не принимают архивы и вложения. Нужен детерминированный текстовый формат склейки. Он же используется как формат «отдай мне кусок проекта одним файлом» для ручной вставки в веб-интерфейс.

Формат маркеров **обязан** совпадать с тем, что уже понимают ваши промпты и о чём предупреждает спецификация `ap`:

```
=== BEGIN path/to/file.go ===
...содержимое как есть...
=== END path/to/file.go ===
```

Полная структура пакета:

```
=== VTPACK 1 ===
root: f4
files: 12
bytes: 148230
generated: 2026-08-12T19:04:11Z

=== TREE ===
f4/
  actions.go
  file_panel.go
  vfs/
    ai_vfs.go
=== END TREE ===

=== BEGIN actions.go ===
package main
...
=== END actions.go ===

=== BEGIN vfs/ai_vfs.go ===
...
=== END vfs/ai_vfs.go ===

=== END VTPACK ===
```

Требования:

- Пути — только относительные, только прямые слеши, отсортированы лексикографически (детерминизм: одинаковый вход → побайтово одинаковый выход).
- Бинарные файлы не включаются; вместо содержимого — строка `<binary, N bytes, sha256:…>`. Определение бинарности: наличие нулевого байта в первых 8 КБ.
- Если файл включён фрагментом — маркер несёт диапазон: `=== BEGIN file_panel.go:412-431 ===`.
- Нумерация строк — **выключена по умолчанию**. Включается опцией; полезна, когда просите модель ссылаться на строки, вредна, когда просите патч (номера просачиваются в сниппеты).
- Распаковка обязана быть реализована симметрично: `vtpack -x` и `F5` из `ai://in/pack.txt` на файловую панель.
- Фильтры: `.gitignore`, `.vtvibeignore`, встроенный чёрный список (`.git/`, `node_modules/`, `vendor/`, `*.exe`, `*.png`, `*.zip`, `testdata/**/*.bin`), лимит на размер файла (по умолчанию 512 КБ, спрашивать про превышение).

`Alt+F5` в **файловой** панели — «упаковать выделенное в один файл»: даёт готовый `pack.txt` для ручной вставки куда угодно. Полезно само по себе, вне зависимости от ИИ-панели.

### 8.2. Сборка запроса: порядок блоков

Порядок принципиален — модели сильнее реагируют на начало и конец запроса.

```
1. Системный промпт роли                 (из presets/<role>.md)
2. Правила формата ap                    (ap.md, целиком, если роль обязана патчить)
3. Постоянная память проекта             (mem/project.md, mem/rules/*.md)
4. Карта проекта                         (mem/map.md — пути и однострочные описания)
5. Файлы контекста, RO                   (vtpack)
6. Файлы контекста, RW                   (vtpack, с явной пометкой «сюда можно писать»)
7. Синтетика: вывод сборки/тестов, git diff, дамп экрана   (_run/, _f4/)
8. История диалога                       (chat/, с усечением, см. ниже)
9. Отклонённые правки прошлого раунда с причинами
10. Текущий вопрос человека              (draft.md)
```

**Усечение истории.** Когда суммарный объём подходит к `soft_limit`:

- никогда не выкидывать: системный промпт, память, `Pinned`-записи, последние два обмена;
- сначала выкидывать самые старые сообщения модели, затем самые старые сообщения человека;
- выкинутое **заменять однострочным резюме** (`[свёрнуто: 4 сообщения об отладке VFS]`), а не удалять молча;
- показывать в панели, что именно свёрнуто, — человек должен видеть, что модель потеряла.

### 8.3. Ответ

Разбор ответа делаем тупо и надёжно:

- ищем блоки в тройных обратных кавычках;
- блок, чьё содержимое соответствует заголовку `[8 hex] AP 3.1` или содержит строки `[8 hex] FILE`, — это патч, кладём в `out/afix.ap`;
- блок с явным именем файла в информационной строке (```` ```go:vtvibe/pack.go ````) — кладём в `out/` под этим именем;
- остальное остаётся текстом сообщения;
- если патчей несколько — склеиваем в один, если ID совпадают; иначе кладём раздельно и предупреждаем.

## 9. Поиск релевантных файлов

Автор считает это отдельной серьёзной проблемой — и правильно считает. Это самое ценное, что vtvibe может дать сверх «чата в панели». Решение — **слоями, от дешёвых к дорогим**, с обязательным ревью человеком на выходе.

### 9.1. Слои

**Слой 0. Детерминированные подсказки (мгновенно, бесплатно).**
- Файл под курсором и его сосед-тест (`x.go` ↔ `x_test.go`).
- Файлы из вывода последней сборки/тестов (парсим `путь:строка:колонка`).
- `git diff --name-only`, `git diff --name-only HEAD~1`, файлы из последних N коммитов.
- Файлы, к которым патчи применялись за последние сеансы (история vtvibe).

Одно это закрывает больше половины реальных случаев. Реализовать первым.

**Слой 1. Лексический поиск (быстро, локально).**
- Триграммный индекс по содержимому для мгновенного подстрочного поиска.
- BM25 по чанкам (чанк = функция или 60 строк, что меньше). Реализуется на Go примерно в 300 строк, без зависимостей.
- Запрос строится из текста промпта + идентификаторов, упомянутых человеком.

**Слой 2. Символьный индекс (структура).**
- Для Go — `go/parser` из стандартной библиотеки: пакеты, типы, функции, методы, импорты. Быстро, точно, без зависимостей. Это родной язык f4, и он должен обслуживаться идеально.
- Для остальных языков — эвристика по регулярным выражениям на «строки объявлений» (`^\s*(func|def|class|fn|function|type|struct|impl|interface)\b`), плюс использование `ctags`, **если он есть в PATH** (не требовать).
- Результат: `символ → файл:строка`, `файл → импортирует[]`, `файл → импортируется[]`.

**Слой 3. Расширение по графу (главное).**
Берём семена из слоёв 0–2 и расширяем:
- файлы, которые определяют символы, упомянутые в семенах;
- файлы, импортирующие семена, и импортируемые семенами (глубина 1, настраивается);
- тесты, покрывающие семена;
- ранжирование: `score = 0.4·bm25 + 0.3·граф + 0.2·свежесть_git + 0.1·совпадение_имени`.

Именно слой 3 находит «релевантные места», а не «файлы, где встретилось слово».

**Слой 4. Модель как ранжировщик (опционально, дёшево).**
Дешёвой модели отдаётся **только карта**: пути + однострочные описания из `map.md` + списки символов. Тела файлов не отправляются. Просим вернуть 5–15 путей с обоснованием в одну строку. Стоит копейки, а качество отбора заметно выше лексики.

### 9.2. Хранение индексов

`.vtvibe/index/` (в `.gitignore`):
```
symbols.json     символы, импорты
lex.bin          триграммы + BM25
hashes.json      путь → sha256 + mtime, для инкрементальной переиндексации
```
Индексация — инкрементальная, в фоне, через менеджер задач, с прогрессом и отменой. Полная переиндексация проекта на 5 000 файлов должна укладываться в несколько секунд.

### 9.3. Панель результатов

`F7` открывает результаты **как панель в стиле результатов поиска файлов** (`Alt+F7` в Far) — то есть в привычном виде:

```
╔═══════════════ Релевантно: «F5 не работает на ai://out» ═════════════════╗
║ ✓ Файл                        │ Балл │ Почему                           ║
╟───────────────────────────────┼──────┼──────────────────────────────────╢
║ ✓ vfs/ai_vfs.go               │ 0.94 │ определяет aiDrive.Open          ║
║ ✓ file_ops.go                 │ 0.81 │ вызывает VFS.Open при копировании║
║ ✓ vfs/vfs.go                  │ 0.77 │ интерфейс VFS                    ║
║   file_ops_test.go            │ 0.62 │ тесты копирования                ║
║   panels_frame.go             │ 0.41 │ импортирует file_ops             ║
╟───────────────────────────────┴──────┴──────────────────────────────────╢
║ Ins выбрать · F5 в контекст · F3 просмотр · Enter открыть · Esc         ║
╚═════════════════════════════════════════════════════════════════════════╝
```

Колонка «Почему» обязательна: непрозрачный поиск теряет доверие после первой же ошибки. Ничего не добавляется в контекст автоматически — только `F5` после просмотра человеком.

### 9.4. Самообучение

После каждого принятого патча записываем в `.vtvibe/index/feedback.json`: какой был запрос, какие файлы предлагались, какие реально понадобились (те, что патч тронул). Раз в N раундов подкручиваем веса ранжирования. Это не машинное обучение, это простая статистика — но она заметно улучшает слой 3 на конкретном проекте за пару недель.

## 10. Постоянная память проекта

```
<корень проекта>/.vtvibe/
    project.md          что за проект, как собирать, как тестировать, стиль кода
    map.md              карта: путь → одна строка «за что отвечает»
    rules/
        ap.md           копия спецификации ap (или ссылка)
        style.md        правила кодстайла проекта
        dont.md         «сюда не лезь»: сгенерированные файлы, vendor, чужой код
    presets/
        architect.md
        coder.md
        reviewer.md
    sessions/           сохранённые сеансы, .jsonl
    undo/               снимки для отката
    index/              кэш (в .gitignore)
```

**`.vtvibe/` лежит в репозитории и коммитится** (кроме `index/` и `undo/`). Это принципиально: память проекта — часть проекта. Её видно в code review, она переживает переустановку, она едет с проектом на другую машину, ей можно делиться.

### 10.1. `map.md` — карта ответственности файлов

Именно то, чего просил автор: «инфа о том, какие файлы в каком проекте за что отвечают, должна фиксироваться в постоянной памяти».

```markdown
# Карта f4

## Ядро панелей
- `panels_frame.go` — менеджер двух панелей, фокус, раскладка, история папок.
- `file_panel.go` — отрисовка и навигация файловой панели; колонки, режимы вида.
- `file_ops.go` — копирование/перемещение/удаление; идёт через VFS.Open+ReadAt.

## VFS
- `vfs/vfs.go` — интерфейс VFS, VFSItem, контракт потокового ReadDir.
- `vfs/ai_vfs.go` — [[vtvibe]] диск ai://; контекст, чат, артефакты.

## Инфраструктура
- `action_registry.go` — реестр действий; источник истины для меню, KeyBar, справки, макросов.
```

**Как поддерживается:**

1. Первичная генерация: `F9 → ИИ → Построить карту проекта`. Идём пакетами по 30 файлов, каждому просим одну строку. Дёшево, делается один раз.
2. Инкрементально: после **принятого** патча файлы, которые он тронул, помечаются как «описание могло устареть». Раз в N патчей одним дешёвым запросом обновляем описания только для помеченных.
3. **Обновление карты приходит обычным `ap`-патчем на `map.md`** и проходит через тот же экран ревью. Память, которую человек утвердил, — память, которой человек доверяет. Никаких молчаливых записей.
4. Хеш содержимого файла хранится рядом (в `index/hashes.json`); если файл поменялся сильно (расстояние по строкам > 30 %), описание помечается устаревшим автоматически.

### 10.2. `project.md` — шаблон

```markdown
# Проект

Имя: f4
Язык: Go 1.24, CGO_ENABLED=0
Сборка: `go build .`
Тесты: `go test ./...`
Линт: `go vet ./...`

## Инварианты, которые нельзя нарушать
- Никаких новых внешних зависимостей без явного согласования.
- Никаких хардкодных обработчиков клавиш: только реестр действий.
- Любое новое действие локализуется в lang/en.lng и lang/ru.lng.
- Рендеринг — без аллокаций в горячем цикле Flush().

## Стиль
- Имена структур держим близкими к оригинальным C++-именам Far.
- Тесты на каждое поведение; клавиши прогонять через хелпер pressKey.
```

Этот файл человек пишет руками один раз. Он же — главный рычаг качества: почти все «модель сделала не то» лечатся строчкой сюда.

## 11. Быстрая обратная связь: цикл «собралось / не собралось»

Прямое требование автора: узнавать о провале раньше, чем сожжены токены.

### 11.1. Кнопка прогона

`Ctrl+Alt+R` (действие `AI.Run`) запускает команду проверки из `project.md` (`go build . && go test ./...`) во встроенном терминале.

- Успех: короткое уведомление, ничего в контекст не идёт.
- Провал: вывод (последние 200 строк + все строки, похожие на `путь:строка:колонка`) автоматически кладётся в `ai://ctx/_run/last-fail.txt`, файлы из ошибок добавляются в контекст как RO (если их там ещё нет), а в строке промпта появляется заготовка: `не собралось: <первая ошибка>`. Один `Enter` — и модель уже чинит.

### 11.2. Автопрогон после применения патча

Настройка `run_after_apply = true` (по умолчанию включена). Применили патч → сразу прогон → при провале сразу готовый запрос. Средний цикл «предложил → применил → упало → починил» сокращается до трёх нажатий.

### 11.3. Ранние сигналы

Ещё до генерации ловим типовые провалы:
- Модель начала отвечать не патчем, хотя роль требует патч → показать плашку «ответ не в формате `ap`» и предложить `Esc` + переспросить. Определяется по первым ~200 токенам потока.
- Модель начала пересказывать содержимое файла целиком → предупреждение о расходе.
- Контекст пуст, а вопрос про код → напоминание «добавьте файлы, `F7` подскажет».

## 12. f4 пишет сам себя: интроспекция и самодиагностика

Это раздел про то, что даёт возможность модели работать **изнутри** f4. Ответ: очень много, потому что TUI сериализуется в текст без потерь.

### 12.1. Синтетические файлы контекста `ai://ctx/_f4/`

Генерируются по требованию, выглядят как обычные файлы, добавляются в контекст через `F5`:

| Файл | Содержимое | Зачем |
|---|---|---|
| `screen.txt` | Дамп `ScreenBuf` в текст (можно с атрибутами в отдельном слое) | Модель **видит** интерфейс. Единственный класс GUI, где это возможно точно. |
| `actions.md` | Полный дамп реестра действий: имя, область, клавиши, путь в меню | Модель перестаёт выдумывать имена действий и клавиши. Резко повышает качество патчей по UI. |
| `frames.md` | Стек фреймов, кто в фокусе, размеры | Диагностика проблем с фокусом и раскладкой. |
| `panels.md` | Состояние панелей: пути, режимы вида, выделение, сортировка | Воспроизведение состояния. |
| `keybar.md` | Текущие метки KeyBar | Проверка, что действие вообще доехало до KeyBar. |
| `log.txt` | Хвост `debug.log`, ключи вырезаны | Обычная отладка. |
| `term.md` | Тип терминала, поддерживаемые протоколы клавиатуры, размер, режим GUI | Половина багов TUI — это баги конкретного терминала. |
| `build.txt` | Вывод последней сборки и тестов | См. §11. |
| `trace.macro` | Последние N действий, записанные как макрос | Воспроизводимое повторение бага. |

`trace.macro` — важная штука. Так как ввод идёт через `vtinput`, а команды через реестр действий, писать трассу почти бесплатно: кольцевой буфер из имён действий и аргументов. На выходе — скрипт, который заново приводит f4 в то же состояние.

### 12.2. Однокнопочный отчёт о баге

`Ctrl+Alt+B` (`AI.BugReport`) собирает в контекст: `screen.txt` + `trace.macro` + хвост лога + `term.md` + версию сборки + `frames.md`, и ставит в черновик шаблон:

```
Баг в f4. Ожидаю: <...>. Получаю: <...>.
Приложены: дамп экрана, трасса действий, лог, окружение.
```

Это полезно и без модели: тот же набор можно приложить к issue на GitHub. Реализуйте кнопку «Сохранить как отчёт» рядом с «Отправить модели».

### 12.3. Headless-прогон: модель смотрит на результат своих правок

Добавить режим:

```
f4 --headless --cols 120 --rows 40 --script check.macro --dump-screen out.txt
```

f4 стартует с фиктивным терминалом (реальный не нужен: `ScreenBuf` — обычная структура в памяти), проигрывает макрос, сбрасывает экран в текст и выходит с кодом возврата.

Что это даёт: **проверяемость изменений UI без человека**. Модель предложила поправить отрисовку панели — f4 собирается, проигрывает сценарий, сравнивает дамп экрана с эталоном. Это и обычные регрессионные тесты (эталонные дампы в `testdata/screens/`), и материал для следующего запроса.

### 12.4. Песочница: `git worktree` и приёмка по `F5`

Главное правило самомодификации: **никогда не применять патч к дереву работающего бинарника вслепую**.

```
Цикл:
1. git worktree add .vtvibe/work <ветка>       (один раз)
2. Патч применяется в .vtvibe/work, не в рабочее дерево
3. go build ./... && go test ./...   в песочнице
4. f4 --headless --script <сценарий> --dump-screen  в песочнице
5. Результат показывается человеку
6. Приёмка
```

И вот приёмка — это буквально две панели:

```
╔════════ ~/src/f4 (моё дерево) ═════════╦═══ .vtvibe/work (собралось ✔ тесты ✔) ═══╗
║   vfs/ai_vfs.go        12 40 12.08     ║   vfs/ai_vfs.go        13 02 12.08  ≠    ║
║   vtvibe/pack.go        8 90 11.08     ║   vtvibe/pack.go        8 90 11.08  =    ║
║   vtvibe/session.go     4 12 12.08     ║   vtvibe/session.go     4 90 12.08  ≠    ║
╚════════════════════════════════════════╩══════════════════════════════════════════╝
                        F5 — принять   Alt+F6 — сравнить папки
```

Слева — ваше дерево. Справа — то, что модель написала, собрала и прогнала. Отличия видны штатным сравнением папок, конкретные файлы разглядываются `F3`, приёмка — `F5`. Никаких новых понятий: человек, всю жизнь проживший в двухпанельнике, понимает этот экран без документации.

**Правила безопасности самомодификации:**
- Песочница обязательна, `sandbox = required` по умолчанию.
- Собранный в песочнице бинарник **не запускается автоматически** в интерактивном режиме — только `--headless` со сценарием и тайм-аутом.
- Тайм-аут на прогон — 120 с, потом убиваем процесс.
- Прогон идёт в отдельной рабочей папке; никаких сетевых доступов у собранного бинарника в режиме проверки (флаг `--no-net`).
- Если патч трогает сам `vtvibe/` или аппликатор `ap` — предупреждение повышенной заметности: вы правите инструмент, которым правите.

## 13. Низкий порог входа

### 13.1. Мастер первого запуска

Три экрана, ни одного обязательного текстового поля кроме одного:

```
┌───────────── vtvibe · настройка (1/3) ──────────────┐
│ Как будем общаться с моделью?                       │
│                                                     │
│  (•) Через буфер обмена — ключи не нужны            │
│      Запрос копируется, ответ вставляете обратно.   │
│  ( ) У меня есть API-ключ                           │
│  ( ) Локальная модель / свой сервер                 │
│  ( ) Внешняя команда (CLI)                          │
│                                                     │
│              [ Далее ]   [ Отмена ]                 │
└─────────────────────────────────────────────────────┘
```

Экран 2 — реквизиты для выбранного варианта (для буфера обмена: ничего, только необязательный URL для открытия браузера). Экран 3 — корень проекта (предзаполнен текущим каталогом) и предложение создать `.vtvibe/` с шаблонами.

Мастер должен завершаться работающим состоянием при выборе варианта по умолчанию и трёх нажатиях `Enter`.

### 13.2. Что должно работать «из коробки»

- Роли `architect`, `coder`, `reviewer`, `explain` — готовые, редактируемые `F4`.
- `f4 --new-vtvibe` — создаёт `.vtvibe/` с шаблонами в текущем каталоге (по аналогии с существующим `f4 --new-plugin`).
- Справка `F1` в панели ИИ — с реальными сценариями, а не описанием полей.
- Все строки локализованы на русский и английский.
- Первый запуск панели без настроенного контекста показывает не пустоту, а подсказку из трёх строк: «`F5` из левой панели — добавить файл. `F7` — найти нужные файлы. Печатайте внизу и `Enter`».

### 13.3. Чего делать нельзя

- Требовать регистрации, ключей, аккаунтов до первого полезного действия.
- Отправлять что-либо в сеть без явного действия человека.
- Молча создавать файлы в проекте пользователя (кроме `.vtvibe/` после явного согласия).
- Показывать больше трёх настроек до первого успешного обмена.

## 14. Безопасность и приватность

| Угроза | Мера |
|---|---|
| Инъекция промпта из содержимого файлов («игнорируй предыдущие инструкции») | Содержимое файлов заворачивается в маркеры `vtpack` и в системном промпте явно объявляется данными, а не инструкциями. Модель не имеет права выполнять команды из контента. Плюс: модель ничего и не исполняет — единственный её выход — патч, который ревьюит человек. |
| Утечка секретов в запрос | Сканер перед отправкой: `.env`, `id_rsa`, `*.pem`, `credentials`, строки вида `sk-…`, `AKIA…`, длинные base64. Найденное — модальное предупреждение со списком и кнопкой «Убрать». Не «предупредить и отправить», а «убрать по умолчанию». |
| Выход патча за пределы проекта | Валидация путей: нет `..`, нет абсолютных, разрешение симлинков и проверка вхождения в корень. |
| Порча файлов | Транзакции + снимки + `Ctrl+Z` (§7.4). |
| Исполнение чужого кода | vtvibe **никогда** не выполняет команды, предложенные моделью. Прогон запускает только команду из `project.md`, которую написал человек. |
| Утечка ключей в логи | Фильтр редактирования в логгере; `debug.log` проверяется на ключи автотестом. |
| Отправка личных данных | Панель контекста показывает всё, что уедет, до отправки. `F3` показывает точные байты. Ничего невидимого. |
| Чужой `.vtvibe/` из склонированного репозитория | При первом открытии проекта с чужим `.vtvibe/` — предупреждение и предложение просмотреть `project.md` и `rules/`: это инструкции, которые получит ваша модель. |

## 17. Ключевые типы

```go
// vtvibe/session.go

type Session struct {
    ID       string
    Role     string
    Provider provider.Provider
    Model    string

    Ctx     *ContextSet
    History []Turn

    Root string // корень проекта

    // Активная генерация; nil, когда простаиваем.
    cancel context.CancelFunc

    mu sync.RWMutex // всё состояние трогается из фоновых горутин
}

type Turn struct {
    Time     time.Time
    Role     provider.Role
    Text     string
    Tokens   int
    Patches  []string // пути в out/
    Rejected []Rejection
}

type Rejection struct {
    HunkID string
    File   string
    Reason string
}

type ContextSet struct {
    Entries []CtxEntry
    Order   []string // ID в порядке отправки
}
```

```go
// vtvibe/ap/apply.go

type HunkStatus int

const (
    StatusOK HunkStatus = iota
    StatusAmbiguous     // сниппет найден больше одного раза
    StatusNotFound
    StatusAlreadyApplied
    StatusReadOnly      // файл помечен RO в контексте
    StatusOutOfRoot     // путь ведёт за пределы проекта
)

type Hunk struct {
    ID       string
    File     string
    Action   string // REPLACE | INSERT_AFTER | INSERT_BEFORE | DELETE | CREATE | RECREATE | RENAME
    Snippet  string
    Tail     string
    Anchor   string
    Content  string
    Status   HunkStatus
    Enabled  bool   // ставится пробелом в ревью
    Line     int    // куда попало, для перехода в редактор
    Preview  Diff   // для правой части экрана ревью
}

type Patch struct {
    ID    string // 8 hex из заголовка
    Hunks []Hunk
    Raw   []byte
}

// Plan считает всё в памяти и НЕ пишет на диск.
func Plan(root string, p *Patch, ctx *ContextSet) error

// Apply пишет только включённые правки, транзакционно.
func Apply(root string, p *Patch) (*Transaction, error)

func (t *Transaction) Rollback() error
```

## 18. Тесты

Обязательный минимум по модулям.

**`ap/`** — самая критичная часть, покрывать плотно:
- каждая директива по отдельности;
- нормализация поиска (отступы, пустые строки);
- граничные якоря `^` и `$`;
- уникальность: ноль совпадений, одно, несколько;
- `anchor` + `snippet`, включая перекрытие и вложенность;
- последовательный курсор: две правки в одном файле, вторая не должна ловить первую;
- идемпотентность: применить дважды, второй раз всё пропущено, файл не изменился;
- каждая эвристика §3.6 спецификации — отдельным тестом;
- пути: `..`, абсолютные, симлинк наружу — все отклоняются;
- транзакция: падение записи третьего файла из четырёх откатывает всё.

**`pack.go`**:
- детерминизм: два прогона — побайтово одинаково;
- бинарники заменяются заглушкой;
- фрагменты с диапазоном строк;
- round-trip: упаковали → распаковали → дерево совпадает;
- фильтры `.gitignore` / `.vtvibeignore`.

**`provider/`**:
- разбор SSE: разрывы посреди события, `\r\n`, комментарии, пустые куски;
- отмена `ctx` посреди потока закрывает соединение и канал;
- ретраи только на 429 и 5xx, уважение `Retry-After`;
- моки на `httptest.Server`, никаких сетевых вызовов в тестах.

**`relevance/`**:
- на маленьком синтетическом дереве: нужный файл входит в топ-5;
- инкрементальная переиндексация после правки одного файла;
- граф: файл, импортирующий семя, поднимается.

**`ui/`**:
- клавиши гонять через `pressKey`, не через голый `ProcessKey`;
- KeyBar и меню содержат новые действия (утверждаем реестр, не дублируем таблицы клавиш);
- эталонные дампы экрана для панели контекста, чата и ревью в `testdata/screens/`;
- `AI.Abort` реально отменяет и возвращает панель в спокойное состояние.

**`secrets.go`**:
- тестовый набор с ключами разных форматов, ни один не должен просочиться;
- проверка, что `debug.log` после сеанса с ключом не содержит ключа.

## 19. План работ

Каждая веха — самостоятельно полезна. Не начинать следующую, пока предыдущая не имеет зелёных тестов.

### M0 — Скелет (готово, когда: панель открывается и закрывается)
- Пакет `vtvibe/`, конфиг, `vfs/ai_vfs.go` с `ReadDir`/`Stat` для пустого сеанса.
- Диск `AI` в меню `Alt+F1`/`Alt+F2`.
- Действия `AI.TogglePanel`, `AI.ViewMode*` в реестре, локализация en/ru.
- **Критерий:** `Alt+F2` → `AI` → видна пустая панель контекста; `F9` содержит пункты; справка `F1` открывается.

### M1 — Контекст (готово, когда: F5 работает в обе стороны)
- `CtxEntry`, `ContextSet`, `VFS.Create`/`Write`/`Remove`/`Open`/`ReadAt`.
- `F5` файла в `ai://ctx`, `F8` из контекста, `F3` экстракта, `Ctrl+A` атрибутов, отслеживание `Stale`, `Ctrl+R`.
- Оценка токенов, индикатор в статусной строке.
- **Критерий:** можно собрать контекст из десяти файлов и фрагментов, увидеть суммарный объём, вытащить экстракт обратно на диск.

### M2 — Первый обмен (готово, когда: пришёл ответ)
- `provider/` с `openai-compatible` и `clipboard`, SSE, отмена.
- Строка промпта, `draft.md`, режим «чат», потоковая отрисовка, `Esc`.
- `prompt.go`: сборка запроса, `pack.go`: vtpack.
- Предполётная проверка и сканер секретов.
- **Критерий:** без единого API-ключа (режим буфера) человек задаёт вопрос с тремя файлами в контексте и получает ответ в панель.

### M3 — Патчи (готово, когда: правка легла в файл по одной клавише)
- `ap/parse.go`, `ap/apply.go` со всеми эвристиками, `ap/tx.go`.
- Экран ревью: список правок, дифф, пробел, `F5`, `F6` сухой прогон, `F8` с причиной, `Ctrl+Z`.
- Разбор ответа на артефакты, `ai://out/`.
- **Критерий:** полный цикл «спросил → патч → ревью → применил → откатил» работает и покрыт тестами.

### M4 — Роли и два сеанса (готово, когда: наряд едет по F5)
- Пресеты, `F2` меню ролей, несколько сеансов, `ai://<session>/`.
- Копирование файлов между сеансами через `F5`.
- Правила `allow_patch` / `require_ap`.
- **Критерий:** сценарий §5 проходится целиком.

### M5 — Релевантность и память (готово, когда: F7 находит нужное)
- `relevance/` слои 0–3, панель результатов, `F7`.
- `.vtvibe/`, `project.md`, `map.md`, генерация и инкрементальное обновление карты через ревью патча.
- `f4 --new-vtvibe`.
- **Критерий:** на самом f4 запрос «почему не работает копирование с `ai://`» выдаёт `vfs/ai_vfs.go` и `file_ops.go` в первых трёх.

### M6 — Обратная связь и интроспекция (готово, когда: баг чинится за три нажатия)
- `AI.Run`, автопрогон после применения, автоподхват ошибок сборки.
- `introspect/`: `screen.txt`, `actions.md`, `trace.macro`, `AI.BugReport`.
- **Критерий:** сломали код → `Ctrl+Alt+R` → ошибка в контексте → `Enter` → патч → применили → зелено.

### M7 — Самомодификация (готово, когда: f4 правит себя в песочнице)
- `--headless --script --dump-screen`, эталонные дампы экрана.
- `git worktree`-песочница, сборка и прогон в ней, приёмка сравнением папок.
- **Критерий:** модель вносит правку в UI f4, песочница собирается, прогоняет сценарий, отдаёт дамп экрана; человек принимает по `F5`.

### Дальше (не в первой версии)
- Провайдеры `anthropic` и `google` нативно (до этого работают через `openai-compatible` и `exec`).
- Слой 4 релевантности (ранжирование моделью).
- Голосовой ввод промпта. Векторный поиск. Экспорт сеанса в markdown.
- Внешний плагин F4-RPC как альтернативный носитель провайдеров.

## 20. Открытые вопросы

1. **`F7` в панели ИИ.** Занят под «Создать папку» в файловой панели. В `ai://` создание папок бессмысленно, поэтому переиспользуем под поиск релевантного. Приемлемо ли это нарушение единообразия, или лучше только `Alt+F7`? Решать автору.
2. **Один сеанс на панель или несколько вкладок в одной панели?** Предложено: один сеанс на панель, переключение через `ai://` корень. Вкладки внутри панели — чужеродная идея для двухпанельника.
3. **Хранение истории.** `.jsonl` в `.vtvibe/sessions/` — коммитить или нет? Предложено: **не коммитить** (в `.gitignore`), в отличие от `project.md` и `map.md`. История часто содержит рабочие черновики и не нужна другим.
4. **Ревью изменений `map.md` через тот же экран патчей** — не будет ли это раздражать при частых мелких обновлениях? Возможен режим «накапливать и показывать раз в N патчей».
5. **Нужен ли режим полного автопилота** (применять без ревью, гонять тесты, повторять до зелёного)? Противоречит принципу 2, но для мелкой рутины (исправить импорты, прогнать `gofmt`) может быть полезен. Если делать — только с явным флагом на сеанс, жёстким лимитом итераций и обязательной песочницей.

## 21. Глоссарий

| Термин | Значение |
|---|---|
| Сеанс (session) | Независимый диалог со своей ролью, провайдером и контекстом. Живёт как `ai://<имя>/`. |
| Запись контекста (entry) | Единица того, что уедет в запрос: файл, фрагмент, папка или синтетика. |
| Роль (role) | Связка «системный промпт + провайдер + ограничения». Например, `architect` или `coder`. |
| Наряд (order) | Продукт роли `architect`: формальное задание для роли `coder`. |
| Правка (hunk) | Одна модификация внутри `ap`-патча. Единица включения/выключения в ревью. |
| Экстракт | Точные байты, в которые превращается запись контекста при отправке. |
| `vtpack` | Формат склейки дерева файлов в один текстовый файл. |
| Песочница | `git worktree` в `.vtvibe/work`, где патч собирается и проверяется до приёмки. |
| Предполётная проверка | Диалог перед отправкой, показывающий объём запроса и крупнейшие записи. |
